# EarthDial: Turning Multi-sensory Earth Observations to Interactive Dialogues

## Problem
Earth observation analysis for disaster response and resource management needs conversational models that handle more than RGB: multispectral, SAR, multi-temporal and multi-resolution imagery. Existing RS assistants were mostly single-sensor, single-date and fixed-resolution.

## Approach
EarthDial (MBZUAI with IBM Research) is a 4B-parameter model built on InternVL2 (InternViT-300M encoder, MLP projector, Phi-3-mini LLM) (Sec. 3.1). Images are tiled into 448x448 tiles (1 to 12 in training, up to 40 at inference) plus a thumbnail. A data fusion module passes multispectral or SAR inputs three channels at a time through the ViT and merges the features with bilinear interpolation; temporal RGB images are encoded separately and stacked. Special modality and task tokens (for example [s1_vh_10], [s2_ms_30], [changedet]) tell the model which sensor and task it is reading (Table 2). Training has three stages: RS conversational pretraining on 7.6M pairs from SatlasPretrain and SkyScript (all components trained), RGB and temporal fine-tuning, then multispectral and SAR fine-tuning with the ViT frozen (Sec. 3.2, Table 3).

## Data and benchmarks
EarthDial-Instruct holds about 11.11M pairs (Table 2): stage 1 NAIP 3.0M, Sentinel-2 2.75M, Landsat 1.67M, SkyScript 0.25M; stage 2 includes change detection 64,631, disaster assessment 37,563 and the GeoChat set 308,861; stage 3 Sentinel-1 VH 1,668,043, LCZ 765,591, tree species 38,527, methane plume 6,849, urban heat island 1,296. Pretraining QA pairs were generated by InternLM-XComposer2 from OSM labels, after dropping images with fewer than 3 labels and filtering cloudy or low-coverage images by a luminance threshold (Appendix A). Evaluation spans 44 downstream datasets.

## Key results
- Scene classification (Table 4): AID 88.76, UCMerced 92.42, WHU-19 96.21 (zero-shot), and supervised BigEarthNet RGB 68.82, xBD set 1 96.37, fMoW 70.03 (GeoChat: 72.03, 84.43, 80.09, 20.35, 53.32, 59.2).
- Multi-band (Table 5): BigEarthNet multispectral 69.94 (1.12 points above RGB; the text says 1.75%), SoSAT-LCZ42 60.72, TreeSatAI RGBI 56.61.
- SAR ship referred detection mAP@0.5 (Table 5): small 12.14, medium 26.02, large 35.56, single 26.03, multiple 6.06, vs GPT-4o 0.7, 0.9, 3.2, 1.2, 0.
- GeoChat-Instruct referred detection: small 11.43, medium 31.76, large 39.07 vs GeoChat 2.9, 13.6, 21.7 (Table 6).
- RSVQA-LRBEN average 92.70, HRBEN 72.45 (Table 10).
- Change captioning ROUGE-1 (Table 11): Dubai CC 31.94, LEVIR-MCI 33.78, MUDS 28.16, SYSU zero-shot 18.03, vs GeoChat 14.21, 17.15, 12.28, 13.45.
- xBD temporal tasks (Table 12): disaster-type recall 96.37; damaged-building detection mAP@0.5 7.6.
- Bi-temporal SAR earthquake detection on QuakeSet: 57.53% vs 55.86% for GPT-4o, close to chance (Sec. 5). UHI 56.77% vs 22.68%; methane plume 77.09% vs 40.93%.
- LoRA rank 128 (about 201M trainable parameters) underperforms full fine-tuning on zero-shot detection (Table A.2).

## Limitations
Failure cases (Fig. A.4, Appendix B.1): ambiguous referring prompts among many similar trees, ships (limited ship data), subtle changes, and similar classes in temporal classification. Small-object and multi-object detection stay low in absolute terms, and SAR change (QuakeSet) is near chance. The sensor is fixed by the input token the user or pipeline supplies; the model does not choose sensors. Training used 4 to 8 A100 80GB GPUs; no inference hardware, CPU or quantisation result is reported, so "CPU possible but slow" is our expectation, not a paper finding. Outputs are text and boxes with no confidence or abstention. The RGB, multispectral and methane/UHI checkpoint split comes from the repo, not the paper.

## What it means for EvidEO
- This is the closest prior VLM to EvidEO's scope (Sentinel-1 plus Sentinel-2, change detection, disaster use): position EvidEO against it explicitly and cite it.
- Strong candidate base for our LoRA fine-tune: open weights, 4B size, already seen Sentinel-1 VH tokens; test a quantized build on our CPU target before committing, and note its own LoRA ablation lost accuracy.
- Adopt its idea of sensor-specific input tokens so the model knows whether it is reading VH SAR or optical bands.
- Beat it on trust, not accuracy: add scene ID, date, region mask, calibrated confidence, abstention and automatic SAR fallback, none of which it provides.
- Its disaster-assessment and change pairs are a useful seed set for flood and crop-damage queries; verify license and Indian coverage.

## Full-text check (2026-10-14)
Ingredients (EarthDial's own system as built and evaluated):
- C1 calibrated per-answer confidence: No. No confidence output or calibration analysis (full text grepped).
- C2 threshold abstention with next step: No.
- C3 scene receipts that reproduce: No. Inputs are dataset chips; no scene IDs, dates or re-run check. Cloud handling appears only as training-data filtering (Appendix A step II).
- C4 SAR chosen automatically under cloud: No. SAR is a separate input type selected by the modality token; there is no automatic sensor choice and no runtime cloud test.
- C5 CPU or offline: No. Open weights could run locally on a GPU, but no CPU or offline answer path is built or measured.
- C6 plain-language questions for non-experts: part. Natural-text queries are supported (Sec. 1, Table A.1 examples), but many tasks need task tokens or option lists and no non-expert study exists.
